# 修复 OpenFuse macOS 字幕时间偏移

你在 OpenFuse 仓库中负责实现并验证 macOS 字幕时间偏移修复。先阅读 [问题报告](MACOS-SUBTITLE-OFFSET-BUG.md)，核对当前工作区和实现。保留工作区已有改动。

## 需要修复

1. **菜单、输入框、播放器和保存值必须一致。** 目前 `0.04` 秒实际延后字幕，菜单却显示「同步（0 秒）」，编辑框预填 `0.0`。对 `0.15` 秒，当前菜单显示 `0.2`，编辑框预填 `0.1`。让所有入口使用同一个有效偏移。沿用 mpv 当前的毫秒精度，十进制显示去掉无意义的尾零。只有有效偏移为零时才显示「同步（0 秒）」。打开编辑框后原样应用应保留有效偏移。校验正负方向、精细小数、从小数值开始的 ±0.1 秒步进和重置。
2. **保留输入的负号，杜绝错误的部分匹配。** `−0.1`（U+2212）、`-0.1` 和 `－0.1`（全角）都应提前 0.1 秒。保留全角正号、逗号小数、外部空白和已支持的「延后 2 秒」等有效输入。对 `-.1` 可以支持为 `-0.1`，也可以交给弹窗报格式错误。对「提前 0.1 秒」应按方向解析为负值，或明确提示需要输入带符号的数字。两种形式都不得静默变成正数。无效输入应保留当前偏移。保留现有的 ±600 秒限幅。
3. **处理已有保存值。** 保持 `subtitle-offsets.json` 的格式兼容和现有影片、轨道键。重开影片、切换字幕轨时用同样的精度规则恢复偏移。无记录时默认 0，重置只清除当前影片和轨道的偏移。用含 `0.04`、`0.15` 等值的既有记录验证恢复行为。

## 实现线索

- `Sources/OpenFuseData/SubtitleOffset.swift` 有解析、菜单文案和偏移存储。
- `Sources/OpenFuseApp/AppModel.swift` 的 `PlayerModel` 有菜单步进、重置、恢复、输入框预填和提交。
- `Sources/OpenFuseApp/PlayerView.swift` 有底栏字幕菜单及 `SubtitleDelaySheet`。如需改变接受的输入形式，同步调整提示文案。
- `Sources/OpenFuseCore/MPVEngine.swift` 的 `setSubtitleDelay` 将偏移传给 mpv。保持正数延后、负数提前的现有约定。
- 使用已有的 Swift 类型与播放入口，变更集中在上述 macOS 偏移链路及相应测试。

## 验收

1. 更新 `Tests/OpenFuseCoreTests/SubtitleOffsetTests.swift` 中预期舍入到一位小数的断言，补充 0、`0.04`、`-0.04`、`0.15` 的显示及输入往返、数学负号、全角负号、部分匹配、±600 秒限幅，以及旧记录恢复和按轨重置。边界值应按同一规则处理，包括舍入到 0 和负零。
2. 运行 `swift test --filter 'SubtitleOffsetTests|SubtitleCatalogTests|PlaybackClockTests'`，并构建 macOS 应用。
3. 用报告里的样片和命令验证用户可见结果。偏移为 0 时，在 5.02 秒能看到从 5.000 秒开始的字幕。设为 `0.04` 后，同一画面没有字幕，菜单和编辑框都能读到 `0.04`。重新打开输入框后直接应用，重开影片或切回该轨时，`0.04` 仍然有效。点「重置为 0」后，5.02 秒处重新显示字幕。粘贴 `−0.1` 时，在 4.95 秒应能看到字幕。尽可能经过正常弹窗验证预填和粘贴，`--sub-delay` 只覆盖应用偏移的路径。
4. 汇报修改的文件、输入和精度规则、通过的命令及播放验证结果。若环境无法操作弹窗，说明已验证的范围和具体限制。
