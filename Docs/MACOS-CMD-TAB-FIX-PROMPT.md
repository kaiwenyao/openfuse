# 修复 OpenFuse macOS 播放视频时 Cmd+Tab 卡顿

你在 OpenFuse 仓库根目录工作。请实现、实测并交付 macOS 的修复。先阅读 `Docs/MACOS-CMD-TAB-PLAYBACK.md`，查看当前 Git 状态并保留已有改动。把变更限定在 macOS 播放器和本任务所需的诊断与回归覆盖。

## 现象与基线

用户反馈，从 OpenFuse 切到其他应用的卡顿仅在持续播放视频时出现。现场用已安装的 0.9.1 验证过主线程栈，0.9.3 也存在同一条路径。现场的 29 次切出中，松开 `Cmd` 到系统切换键盘焦点中位数为 3 ms，屏幕动画需另行测量。0.9.3 用同一个本地 MKV 对照时，播放组主线程有 626/935 个样本落在 libmpv 条件等待中，已确认暂停的对照组为 0/924。

渲染链路是 libmpv 更新回调 → 主队列设置 `needsDisplay` → AppKit 调用 `MPVGLView.draw(_:)` → `MPVEngine.render(into:)` → `mpv_render_context_render` → OpenGL `flushBuffer()`。默认 `video-sync=audio`，libmpv 可能等待目标呈现时刻。首先查看 `Sources/OpenFuseCore/MPVGLView.swift`、`Sources/OpenFuseCore/MPVEngine.swift`、`Sources/OpenFuseApp/PlaybackTrace.swift`，并核对当前 libmpv 的 `mpv/render.h`。

## 实现顺序

1. 用调查文档的样片建立改前指标。在可关闭的诊断模式下区分 libmpv 渲染、交换报告、交换缓冲、截图读回及整次绘制耗时，并记录播放状态与切换时序。用实体 `Cmd+Tab` 测用户路径，通过系统激活的脚本用作可重复的采样对照。
2. 首先在 macOS 使用 `NSOpenGLView` 的交互式播放引擎初始化时尝试 `video-timing-offset=0`，使用默认 `audio` 模式做单变量 A/B。保留现有 8-bit sRGB 表面、字幕和硬解路径，以及其他同步模式、无界面和缩略图引擎的设置。若用 `MPV_RENDER_PARAM_BLOCK_FOR_TARGET_TIME=0` 做定位对照，按 libmpv 文档处理目标帧时序，并独立验证 A/V 同步。根据渲染等待、实际窗口画面和媒体回归选择最小的有效实现。
3. 若 libmpv 等待下降而屏幕仍有掉帧，再检查 `flushBuffer()`、AppKit 合成和可见性。只有相应数据指向这些路径时才扩大改动范围。保留前后台播放、后台声音和播放进度的现有行为。任何渲染线程或可见性改动均需保持正确的 GL 上下文所有权、帧消费、回调释放、切回重绘及换集、关闭时的安全。历史图层方案出现过 SRT 缺失与 XDR 偏色，采用新呈现表面时要用实际图像回归验证。

## 验收与交付要求

- 在同一设备和片源下比较改前改后。普通窗口、原生全屏各覆盖至少 20 次真实切出、切回，记录播放、暂停和首页对照。收集切换栏和目标窗口的屏幕呈现证据，量化长帧、p95 和最差轮次。系统焦点时间作为辅助指标。若无法录制或读取呈现时间，报告手动观察、实测环境和缺失的屏幕指标。
- 对比主线程采样占比和分段耗时，并检查渲染、交换缓冲长尾及掉帧计数。用有声样片和正常音频输出验证背景音频、进度连续和 A/V 对齐。验证首帧、暂停/恢复、跳转、变速、换集与关闭，覆盖本地和已有测试远程源。
- 用实际画面验证 SRT、ASS、SDR、HDR/XDR 和播放器截图。运行 `swift test`、macOS 构建和调查文档列出的适用回归脚本。执行 UI 脚本前查看其对当前前台窗口和应用配置的影响。
- 最终列出修改文件、选定方案、复现与验证命令、改前改后数据、已完成的回归和仍待验证的分支。交付源代码修复及必要的测试或诊断改动。默认的应用交互、快捷键和后台行为以仓库当前实现为准。
